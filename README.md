# ClipMini

一个轻量的 macOS 剪贴板历史工具。

当前为 1.34 精简版：移除个人工作台菜单、Control+M 快捷键和窗口初始化。旧工作台源码与本地数据保留，精简版不会启动工作台。

- 自动记录文字、图片和文件
- 最多保存 50 条，重启后仍保留
- 图片独立保存，单张最大 10 MB
- 按 `Control+X` 打开底部横向历史，也可以点菜单栏的剪贴板图标
- 单击卡片或按回车后直接粘贴
- 支持左右方向键切换，按 `Esc` 关闭
- 可在菜单栏选择贴底横向面板或菜单栏下方小视窗
- 支持登录时启动
- 支持搜索和单条删除
- 支持为本机应用绑定自定义全局快捷键
- 自动粘贴需要在 macOS 系统设置中授予一次“辅助功能”权限

## 个人工作台（1.17）

菜单栏选择“个人工作台…”打开居中的独立窗口，关闭工作台不会退出剪贴板工具。

- 名字、鼓励语可编辑；使用原 App 图标作为头像。
- 今日任务按日期保存，支持勾选、添加和删除；旧日期任务不会被自动删除。
- 快捷应用复用原来的快捷启动配置。
- 常用入口支持本机文件夹；移除入口不会删除文件夹。
- 随手记自动保存，使用当前用户的本地 UserDefaults。
- Codex 额度：调用本机官方 Codex 的 `app-server`，完成初始化后读取 `account/rateLimits/read`。第一次打开工作台立即查询，之后每 2 分钟自动查询，并接受额度更新通知。没有手动刷新按钮、硬编码百分比或日志推算额度。未知窗口显示不可用，不当作零；失败时旧数据带最后成功时间。需要官方桌面 App 或 CLI 已通过 ChatGPT 登录。仅 API Key 登录不保证能读取 ChatGPT 额度。
- Codex 进程使用独立 `ClipMini/CodexRuntime` 状态目录，关闭分析上报，不创建会话或调用模型，不消费额度重置。
- 星象：设置城市名称与有效经纬度后，顺序查询 NASA Horizons 的金星、木星方位角/高度角。首次地点不默认猜测。星图是简化地平坐标投影，负高度表示地平线下，不保证肉眼可见。月相为本地朔望周期近似计算，不用于精密观测。
- 万年历：公历与农历、闰月、月视图和今天标记；当前未接入节气和法定调休数据。

Codex 协议参考：https://developers.openai.com/codex/app-server

天文接口参考：https://ssd-api.jpl.nasa.gov/doc/horizons.html

### 当前验证边界

Release 构建、签名校验和额度解析回归测试通过。开发沙盒仍阻止官方 Codex app-server 的完整启动；NASA 地址在测试网络连接超时。因此在线额度、在线星象和真实窗口交互尚未完成端到端验证。1.17 是可体验版本，不应当将其视为在线功能已验证完成。

## 构建

```bash
chmod +x build-app.sh
./build-app.sh
```

生成的应用位于 `outputs/ClipMini.app`。

## 隐私说明

历史记录会以普通文件保存在当前用户的 `~/Library/Application Support/ClipMini/history.json`。密码、验证码等敏感内容如果经过系统剪贴板，也可能被记录。菜单栏里可以随时清空历史。

工作台个人配置、任务和便签只保存在本机，不随额度或天文请求上传。额度请求由官方 Codex 使用既有登录处理，ClipMini 不读取/复制认证 Token 或账号密码。天文请求向 NASA 发送你设置的观测经纬度与观测时刻；不申请系统定位。新增在线模块意味着软件不再是完全不联网的工具。

## 桌面信号（1.35 本机体验版）

- 保留精简版剪贴板，不恢复个人工作台。
- 菜单栏“授权／重试桌面信号”申请辅助功能权限；授权后再次点击重试。
- 按住 Control+Option，按下鼠标左键并拖动选择八方向信号，松开鼠标发出。中心松开、Esc 或右键取消。
- 菜单栏可关闭信号或静音。首次缺少设置时默认开启、音效不静音。
- “请求支援”读取手势开始时前台应用的可见主窗口，不读取其他窗口或全部桌面；首次需要屏幕录制权限，授权后可能需要重启。受保护窗口可能无法截取，截图不包含滚动区域之外的内容。
- 截图先在独立支援窗口预览。ChatGPT：复制截图并打开应用（未安装则打开网页），手动 Command+V 粘贴并提问。Codex：点击按钮后使用本机 CLI、已有登录及模型配置分析图片，结果在支援窗口显示，可取消，180 秒超时；会消耗账号额度或按已有 API 配置计费。
- Codex 以只读沙盒、临时会话运行；截图临时目录结束后删除，不自动读取完整应用文件。强制结束 ClipMini 可能留下系统临时文件。
- 图标与音效来自 https://github.com/darrenprx/lolPing ，归 Riot Games 所有，不属于 MIT 授权。动画沿用该项目 CSS 复刻效果，并非游戏引擎原版动画。来源与声明位于 Resources/Pings/NOTICE.txt。
- Control+Option 可能与 VoiceOver 或其他应用快捷操作冲突，可通过菜单关闭信号。
- 本机交互、多显示器、全屏覆盖、权限授权及在线 AI 返回仍需真机验证；联机未实现。

## 1.36 轮盘交互修订

按住 Control+Option 即在鼠标位置显示轮盘，无需按住鼠标。移动鼠标选择，松开任一快捷键或左键点击确认；中心松开、Esc、右键取消。轮盘恢复 lolPing 的原始 SVG 扇形、渐变、中心圆和悬停高亮。图标/音效仍为 LOL 素材，动画为桌面复刻。

音效改用预加载 AVAudioPlayer，信号音量为原素材音量；新增菜单“试听信号音效”（试听忽略信号静音设置）。原 App 内的素材解码与独立播放探针均成功，尚未复现用户环境的无声原因，因此需要替换新版后试听确认。

验证：Release 构建、签名；WebKit 实际加载轮盘、八方向图标/扇形、请求支援选中和双贴图动画；音效解码与本机播放返回成功。全局按键交互和用户实际听感仍需真机验收。

## 1.37 心之钢彩蛋

保持八方向信号布局。按住 Control+Option 打开轮盘，中心显示心之钢图标并高亮；左键点击中心播放叠钢音效与金色冲击动画。中心直接松开快捷键仍然取消，不触发音效。沿用信号静音设置，叠钢最短间隔为 2 秒。

装备图标来自官方 Data Dragon。音效采用 Myinstants 社区分享的 LoL Heartsteel 版本，已转换为 PCM WAV；无法独立确认原始游戏提取链路。具体地址和归属见 App 资源内 Pings/NOTICE.txt。

## 1.38 完整蓄力与全屏冲击

按住 Control+Option，鼠标停在中心：三声叠层音效与三层金色光圈依次出现，约 1.4 秒蓄满。蓄满前点击不会触发，蓄满后点击播放“铛”和金色全屏扩散波。鼠标移出中心、松开快捷键、Esc 或右键都会取消蓄力并停止待播放声音；回到中心重新开始。中心松开仍然取消，不会自动叠钢。

全屏指鼠标所在显示器：透明、非激活窗口，点击穿透，三道冲击波从触发位置扩散到屏幕四角，约 1.8 秒自动消失；不移动其他应用窗口。保留原有八方向信号、静音和 2 秒冷却。

本版叠层、就绪和触发音效来自 League of Legends Wiki 的 Heartsteel Sound Effects 分类，转换为 PCM WAV，来源路径保存在 Pings/NOTICE.txt；归 Riot Games 所有。

验证包括实际蓄力/触发方法的时序、取消、冷却检查，WebKit 三层光圈与心之钢动画，原生全屏窗口的尺寸、透明、点击穿透和覆盖范围，以及音效播放返回值。跨显示器和真实全屏应用覆盖仍需真机体验。

## 1.40 同一 Wi-Fi 联机

菜单栏“联机房间…”填写昵称；一人“创建局域网房间”并“复制邀请”，朋友复制邀请后“粘贴邀请”并“加入房间”。原生 Network.framework 中转内置在 App，局域网使用无需 Python 或额外脚本。最多 4 人，同步八种普通信号。接收在主显示器右下区域显示昵称与动画，音效遵循原有静音；可暂停接收。心之钢、截图、剪贴板和 AI 不广播。退出房间或关闭房主 App 会关闭局域网房间。首次需要允许本地网络和防火墙访问。

断线后手动重入，不补发旧消息；同一 Wi-Fi 的客户端隔离可能阻止互通。当前通过同机真实客户端与内置服务通信验证，两台实体 Mac 的网络、授权和视听链路仍待验收。Relay/ 是兼容的 Python 公网中转预备实现，尚未部署；本轮不依赖它。

## 1.45 心之钢同步、10 人与比例坐标

- 局域网及预备公网中转均扩充到 10 人，第 11 人会被明确拒绝。
- 心之钢蓄力仍在本机；蓄满点击后，把最后的音效、图标和全屏冲击传给朋友。暂停接收和静音继续生效，接收方心之钢有 2 秒冷却。
- 标记锚点取呼出轮盘时的鼠标位置，按发送方当前屏幕完整尺寸计算横纵比例，映射到接收方鼠标所在显示器；不用固定右下角。兼容不同尺寸与位于负坐标的副屏，动画中心修正为准确锚点。
- 比例同步只对齐屏幕位置，不保证对齐不同窗口里的相同内容。
- 协议升级到 v2，双方需要 1.45 或以上。旧版会提示版本不兼容。仍需先创建房间并分享最新邀请，不能修复 Wi-Fi 隔离或已经失效的端口。
- 验证：同机真实客户端的心之钢/坐标收发、暂停恢复、10 人入房与拒绝第 11 人、负坐标屏幕映射；远端心之钢 WebKit 与独立原生全屏浮层；预备公网中转测试。两台实体 Mac 的实际视觉位置与声音仍待验收。

## 1.46 多标记、叠钢次数、Wi-Fi 与房间发现

- 本机和收到的标记共用独立透明画布，最多同时显示 30 个，每个分别消失。重新打开轮盘不会清掉已有标记；多个普通信号不再被全局接收间隔丢弃。心之钢标记全部显示，全屏强冲击与其声音仍限制 2 秒一次。
- 房主中转统一统计每位成员本次入房后成功发送的心之钢次数，在成员列表和心之钢标签显示；重新入房清零。未入房时本机次数按当前会话累计。
- 房间顶部读取当前 Wi-Fi 名称。macOS 可能需要定位权限，点击“读取 Wi-Fi”申请；不读取实际位置、不上传 SSID。无法取得名称会明确显示权限或不可用状态，不猜测网络名。
- “加入房间”下方增加 Bonjour 自动发现列表，显示房主昵称及人数，点击加入自动填地址和房间码，不需要账号密码，仍需填写昵称。房主退出后房间会从列表移除。邀请粘贴保留作为备用。
- Bonjour 发现覆盖可互通的局域网，不保证严格等同于同一 SSID，访客隔离或禁用组播可能阻止发现。双方升级 1.46 后使用完整功能。
- 验证：同机真实 Bonjour 发布/发现/解析/免手输加入及退出移除；成员叠钢计数；10 人房间与位置同步回归；WebKit 同时三标记、独立错峰过期和 30 个上限；界面预览。两台实体 Mac、定位授权后的 SSID、跨显示器视听体验仍待验收。

## 1.47 标记显示时序修复

复现了旧版页面加载超过 3.5 秒时画布先隐藏、随后标记执行却看不到的时序问题，可能出现有音效无图像。现在隐藏计时从 WebKit 确认渲染执行后开始，并通过代次检查避免旧隐藏任务影响新标记。每块显示器使用独立透明画布，替代跨显示器联合大画布；网页进程中断后，下一条标记自动重新加载，渲染与加载错误记录到系统日志的 [ClipMini Marker] 前缀。

验证：旧逻辑在 4 秒延迟页面下稳定复现隐藏问题；修复版实际 MarkerCanvas 的慢加载、新旧隐藏时序、模拟网页进程中断恢复回归通过。Release、签名及解压后资源检查通过。尚不能排除其他设备的网络或全屏应用覆盖问题，两台实体 Mac 与不同桌面空间待实际验收。协议仍为 v2，兼容 1.46。
